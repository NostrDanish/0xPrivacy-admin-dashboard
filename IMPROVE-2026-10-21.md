## Top recommendations (ranked, with effort S/M/L)

1. **Signer-only + NWC at-rest migration (M)** — same shared pattern as the other 0xPrivacy sites: `useNWC.ts` persists full `nostr+walletconnect://` connection strings (wallet spend secret) in plaintext localStorage (`nwc-connections`), and Nostrify login persistence stores raw nsecs for nsec logins. For an ADMIN dashboard this is the highest-stakes repo of the set — an XSS or malicious dep here yields both the admin identity and a spending credential. Same fix as detailed in the 0xPrivacy IMPROVE doc: NIP-07/NIP-46-first login UI, nsec session-only behind an advanced toggle, NWC connection string encrypted at rest (NIP-49-style passphrase or NIP-44-to-self) or session-only.
2. **Consider gating admin behind signer-only entirely (S)** — for this specific app, dropping raw-nsec login completely (extension/bunker only) is a cheap, defensible hardening decision; admin pubkeys are few and known.
3. **Dep alignment with sister repos (S–M)** — see table; the repo carries the oldest stack of the family (@getalby/sdk ^5.1.1 vs latest 8.0.3; vite ^8.0.3 below the 8.0.5/8.0.16 security fixes; nostr-tools ^2.13.0 vs 2.25.2).
4. **Add CI test gate (S)** — only `.gitlab-ci.yml` (1-minute timeout, GitLab Pages template) and no GitHub workflow that runs `npm run test`; build/test scripts even self-run `npm i --silent` inside, defeating lockfile discipline. Add a PR workflow running `npm ci && npm run test`.
5. **De-duplicate the scaffold (M)** — package.json/hooks/AGENTS.md (51 KB, identical size across repos) are copy-pasted across 0xPrivacy, this repo, and 0xPrivacyOnline-nostr-live. Extract shared hooks (login, NWC, nostr publish) into a small internal package or accept one-directional sync from 0xPrivacy; today a fix (e.g. the NWC storage fix) must be applied 3+ times and will drift.
